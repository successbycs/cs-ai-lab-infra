# ADR 0001: private, isolated Penpot deployment

- Status: accepted for localhost-only deployment
- Date: 2026-09-11
- Owner: Chris

## Context

Pt Chev Water Times and Shamatha Timer need a shared, agent-editable design
workspace without coupling design authority to either product repository or a
paid Figma seat. The T480 already provides a private WSL/Docker runtime with a
fixed-operation controller boundary.

Read-only discovery found Windows 11 Pro with 15.8 GiB RAM, Docker 29.7.2,
Compose 5.4.0, a healthy existing lab stack, a clean T480 infrastructure
checkout, and no repository-managed reverse proxy or certificate service.
Existing application ports are predominantly loopback-only; the status-only
dashboard is the sole approved LAN publication. At discovery time the Windows
system drive had approximately 26 GiB free (11%), while the WSL filesystem
reported approximately 906 GiB available. The discrepancy means Windows/VHDX
growth remains the binding capacity risk.

## Decision

Run Penpot as the separate Compose project `penpot-private` with official
Penpot 2.17.2 frontend, backend, exporter, and MCP images; PostgreSQL 15.18;
and Valkey 8.1.4. Pin every image by version and registry digest.

Publish only `127.0.0.1:9001`. Do not add DNS, router forwarding, a Windows
firewall exception, LAN publication, public ingress, or a new reverse proxy.
Human access is local to the T480 or through the existing authenticated SSH
path using a local port forward.

Keep database, assets, and Valkey in Penpot-specific named volumes. Store live
secrets outside Git at `/home/chris/.config/cs-ai-lab/penpot.env`. Disable
registration, SMTP, and telemetry. Create accounts with the backend management
CLI so no default password or open sign-up window is required.

Use the official Penpot MCP container in remote mode. Its bundled plugin has
design content/library/comment permissions but no filesystem-download or user
permission; remote mode omits local import and developer/REPL tools. The MCP
container has a read-only root filesystem, no host bind mounts, no Docker
socket, no product repository, and no cloud credentials. Agents connect via a
separate Penpot account and MCP key while a human has explicitly opened and
connected the intended file.

## Consequences

- The initial endpoint is private but plain HTTP. Clipboard features may be
  limited; it is not suitable for non-local exposure.
- Shared human access awaits an approved private HTTPS ingress decision.
- The official MCP bridge is live-file scoped and requires an active browser
  tab/plugin connection. It is not a headless repository design API.
- A Penpot MCP key is account-scoped for authentication, while effective
  design execution is the currently connected file. Use a dedicated account
  containing only disposable/shared design work to avoid broader design
  visibility.
- PostgreSQL and asset backups are recoverable together. Valkey is transient
  coordination state and is recreated rather than restored. The master secret
  must be protected separately from the backup bundle.
- Total configured maxima are 4.75 CPUs and 4.96 GiB. These are ceilings, not
  reservations; simultaneous export and existing AI workloads may contend.

## Rejected alternatives

- Adding Penpot to the existing root Compose file: unnecessarily couples
  lifecycle and recovery to PostgreSQL/n8n/Ollama.
- Publishing directly to the LAN over HTTP: violates the approval and HTTPS
  controls and weakens browser/session behavior.
- Giving OpenWorker SSH or Docker access: creates general host authority far
  beyond design operations.
- A token-only third-party Penpot API bridge: broader account/project scope
  and a larger unaudited dependency surface than the official live-file MCP.
- Migrating existing Figma content: explicitly outside this change.
